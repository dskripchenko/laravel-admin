# i18n

Two layers:

1. **UI translation** — admin chrome, field labels, menu titles.
2. **Content translation** — Eloquent model fields stored per-locale
   (via `dskripchenko/laravel-translatable`).

## Locale resolution

`LocaleResolver` (applied by the `AdminLocale` middleware) takes the first
of these that is in `config('admin.ui.available_locales')`:

1. `?locale=en` query param (explicit override, for testing and previews)
2. `X-Admin-Locale` header (sent by the SPA)
3. the logged-in user's `locale` attribute
4. `admin_locale` cookie
5. `Accept-Language` header (`ru-RU` falls back to `ru`)
6. `config('admin.ui.default_locale')` (`ADMIN_LOCALE`), or the application
   locale when it is not set

Selected locale is applied via `app()->setLocale()` and exposed in the
bootstrap (`locale`, `availableLocales`) and in the manifest.

## UI language packs

The package ships two kinds of strings, both delivered to the SPA in the
bootstrap's `translations` bag:

- `resources/lang/{en,ru}/admin.php` — the `admin::` namespace, nested
  arrays flattened to keys like `admin.common.save`; the frontend reads
  them with `t('admin.common.save')`.
- `resources/lang/en.json` — a JSON dictionary keyed by the Russian source
  string; the frontend's `tr()` translates the components' built-in strings
  through it.

Both are ordinary Laravel translations, so a host overrides them the
Laravel way:

```php
// lang/vendor/admin/de/admin.php — the admin:: namespace for a new locale
return [
    'common' => [
        'save' => 'Speichern',
        'cancel' => 'Abbrechen',
    ],
    // ...
];
```

and adds or overrides JSON strings in its own `lang/{locale}.json`.

Your own labels (resource and field labels, menu titles, action labels,
confirm texts) do not need `__()`: when the manifest and the schemas are
serialized they are passed through the JSON translations of the request's
locale, and a string without a translation comes back unchanged.

## SPA locale change

```ts
const locale = useLocaleStore()
await locale.setLocale('de')
```

Updates `<html lang>`, makes every later request carry `X-Admin-Locale`,
and sends POST `/api/admin/system/setLocale {locale: 'de'}`. A locale not in
`available_locales` is rejected with 422. The server saves it to the
logged-in user's `locale` attribute and sets the `admin_locale` cookie
(a year).

## Content translation (models)

Use `dskripchenko/laravel-translatable`. The admin does not require it;
install it yourself (`composer require dskripchenko/laravel-translatable`,
then `php artisan migrate` for its tables):

```php
use Dskripchenko\LaravelTranslatable\Traits\TranslationTrait;

class Article extends Model
{
    use TranslationTrait;
}
```

Reading:

```php
use Dskripchenko\LaravelTranslatable\Models\Language;

$article->t('title');                                  // current locale
$article->t('title', null, Language::byCode('de'));    // explicit
Article::whereTranslation('title', 'Hi')->get();
Article::whereTranslation('title', 'like', 'Hi%', 'de')->get();
Article::orderByTranslation('title')->get();
```

## TranslatableField

The admin's `TranslatableInput` renders a tabbed input — one tab per
locale:

```php
TranslatableInput::make('title')->locales(['en', 'ru', 'de']),
```

Without `locales()` it uses `config('admin.ui.available_locales')`;
`->as('textarea')` (or `markdown`, `wysiwyg`) changes the inner control,
`->requireAllLocales()` makes every locale required. The form state is a
`{locale: value}` map; on create/update the bridge layer
(`TranslatableFieldBridge`) takes it out of the payload and saves each
locale through the model's `TranslationTrait`.

## Adding a locale

1. Create `lang/vendor/admin/{locale}/admin.php` and `lang/{locale}.json`
   (missing keys fall back to Laravel's fallback locale).
2. Add the locale to `config('admin.ui.available_locales')`:
   ```php
   'ui' => [
       'default_locale' => 'en',
       'available_locales' => ['en', 'ru', 'de', 'zh'],
   ],
   ```
3. The locale-switcher in the topbar populates from this list.

## Best practices

- Write labels as plain source strings and translate them in
  `lang/{locale}.json` rather than wrapping them in `__()` at boot.
- Don't translate code identifiers (slugs, role keys, settings keys).
- Date/number formats — use ICU via `Intl` (`new Intl.DateTimeFormat`
  on frontend), don't hand-roll.
- For long-form translatable content, prefer `TranslatableInput` over
  multiple plain Input fields per locale.
