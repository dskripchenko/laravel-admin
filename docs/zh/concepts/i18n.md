# i18n

分为两层：

1. **UI 翻译**——管理界面外壳、字段标签、菜单标题。
2. **内容翻译**——按 locale 存储的 Eloquent 模型字段
   （通过 `dskripchenko/laravel-translatable`）。

## locale 解析

`LocaleResolver`（由 `AdminLocale` 中间件应用）取以下来源中第一个位于
`config('admin.ui.available_locales')` 内的值：

1. `?locale=en` 查询参数（显式覆盖，用于测试和预览）
2. `X-Admin-Locale` header（由 SPA 发送）
3. 已登录用户的 `locale` 属性
4. `admin_locale` cookie
5. `Accept-Language` header（`ru-RU` 回退为 `ru`）
6. `config('admin.ui.default_locale')`（`ADMIN_LOCALE`），未设置时使用应用的
   locale

选定的 locale 通过 `app()->setLocale()` 应用，并在 bootstrap
（`locale`、`availableLocales`）和 manifest 中暴露。

## UI 语言包

本包提供两类字符串，二者都通过 bootstrap 的 `translations` 集合交付给 SPA：

- `resources/lang/{en,ru}/admin.php`——`admin::` 命名空间，嵌套数组被展平为
  `admin.common.save` 这样的键；前端通过 `t('admin.common.save')` 读取。
- `resources/lang/en.json`——以俄文源字符串为键的 JSON 字典；前端的 `tr()`
  通过它翻译组件的内置字符串。

二者都是普通的 Laravel 翻译，因此宿主可以按 Laravel 的方式覆盖它们：

```php
// lang/vendor/admin/de/admin.php — 新 locale 的 admin:: 命名空间
return [
    'common' => [
        'save' => 'Speichern',
        'cancel' => 'Abbrechen',
    ],
    // ...
];
```

并在自己的 `lang/{locale}.json` 中添加或覆盖 JSON 字符串。

你自己的标签（Resource 和字段标签、菜单标题、Action 标签、确认文本）不需要
`__()`：manifest 和 schema 在序列化时会经过当前请求 locale 的 JSON 翻译，没有
翻译的字符串会原样返回。

## SPA 切换 locale

```ts
const locale = useLocaleStore()
await locale.setLocale('de')
```

更新 `<html lang>`，让之后的每个请求都携带 `X-Admin-Locale`，并发送 POST
`/api/admin/system/setLocale {locale: 'de'}`。不在 `available_locales` 中的
locale 会以 422 被拒绝。服务端会将其保存到已登录用户的 `locale` 属性，并设置
`admin_locale` cookie（有效期一年）。

## 内容翻译（模型）

使用 `dskripchenko/laravel-translatable`：

```php
use Dskripchenko\LaravelTranslatable\Traits\TranslationTrait;

class Article extends Model
{
    use TranslationTrait;
}
```

读取：

```php
use Dskripchenko\LaravelTranslatable\Models\Language;

$article->t('title');                                  // 当前 locale
$article->t('title', null, Language::byCode('de'));    // 显式指定
Article::whereTranslation('title', 'Hi')->get();
Article::whereTranslation('title', 'like', 'Hi%', 'de')->get();
Article::orderByTranslation('title')->get();
```

## TranslatableField

管理面板的 `TranslatableInput` 渲染一个带标签页的输入框——每个 locale 一个
标签页：

```php
TranslatableInput::make('title')->locales(['en', 'ru', 'de']),
```

不调用 `locales()` 时，它使用 `config('admin.ui.available_locales')`；
`->as('textarea')`（或 `markdown`、`wysiwyg`）更改内部控件，
`->requireAllLocales()` 使每个 locale 都成为必填。表单 state 是一个
`{locale: value}` 映射；在创建/更新时，桥接层（`TranslatableFieldBridge`）
将其从 payload 中取出，并通过模型的 `TranslationTrait` 保存每个 locale。

## 添加 locale

1. 创建 `lang/vendor/admin/{locale}/admin.php` 和 `lang/{locale}.json`
   （缺失的键会回退到 Laravel 的 fallback locale）。
2. 将该 locale 添加到 `config('admin.ui.available_locales')`：
   ```php
   'ui' => [
       'default_locale' => 'en',
       'available_locales' => ['en', 'ru', 'de', 'zh'],
   ],
   ```
3. 顶栏中的 locale 切换器会根据此列表填充。

## 最佳实践

- 把标签写成普通的源字符串，并在 `lang/{locale}.json` 中翻译，而不是在启动时
  用 `__()` 包裹。
- 不要翻译代码标识符（slug、角色键、设置键）。
- 日期/数字格式——通过 `Intl` 使用 ICU（前端用 `new Intl.DateTimeFormat`），
  不要自己手写。
- 对于长篇的可翻译内容，优先使用 `TranslatableInput`，而不是为每个 locale
  各用一个普通 Input 字段。
