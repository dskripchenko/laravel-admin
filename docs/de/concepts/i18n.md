# i18n

Zwei Ebenen:

1. **UI-Übersetzung** — Oberfläche der Administration, Feldbeschriftungen,
   Menütitel.
2. **Inhaltsübersetzung** — Felder von Eloquent-Modellen, die pro Locale
   gespeichert werden (über `dskripchenko/laravel-translatable`).

## Ermittlung der Locale

`LocaleResolver` (angewendet durch die Middleware `AdminLocale`) nimmt die erste
der folgenden Quellen, deren Wert in `config('admin.ui.available_locales')`
enthalten ist:

1. Query-Parameter `?locale=en` (explizite Überschreibung, für Tests und Vorschauen)
2. Header `X-Admin-Locale` (von der SPA gesendet)
3. das Attribut `locale` des angemeldeten Benutzers
4. Cookie `admin_locale`
5. Header `Accept-Language` (`ru-RU` fällt auf `ru` zurück)
6. `config('admin.ui.default_locale')` (`ADMIN_LOCALE`) oder die Locale der
   Anwendung, wenn diese nicht gesetzt ist

Die ausgewählte Locale wird über `app()->setLocale()` angewendet und im
Bootstrap-Payload (`locale`, `availableLocales`) sowie im Manifest bereitgestellt.

## UI-Sprachpakete

Das Paket liefert zwei Arten von Zeichenketten aus, die beide im
`translations`-Bündel des Bootstrap-Payloads an die SPA übergeben werden:

- `resources/lang/{en,ru}/admin.php` — der Namespace `admin::`, verschachtelte
  Arrays zu Schlüsseln wie `admin.common.save` abgeflacht; das Frontend liest
  sie mit `t('admin.common.save')`.
- `resources/lang/en.json` — ein JSON-Wörterbuch, dessen Schlüssel die russische
  Quellzeichenkette ist; `tr()` im Frontend übersetzt darüber die eingebauten
  Zeichenketten der Komponenten.

Beides sind gewöhnliche Laravel-Übersetzungen, daher überschreibt ein Host sie
auf Laravel-Art:

```php
// lang/vendor/admin/de/admin.php — der Namespace admin:: für eine neue Locale
return [
    'common' => [
        'save' => 'Speichern',
        'cancel' => 'Abbrechen',
    ],
    // ...
];
```

und fügt JSON-Zeichenketten in seiner eigenen `lang/{locale}.json` hinzu oder
überschreibt sie.

Ihre eigenen Beschriftungen (Beschriftungen von Resources und Feldern, Menütitel,
Beschriftungen von Actions, Bestätigungstexte) benötigen kein `__()`: Beim
Serialisieren des Manifests und der Schemas werden sie durch die
JSON-Übersetzungen der Locale des Requests geleitet, und eine Zeichenkette ohne
Übersetzung kommt unverändert zurück.

## Locale-Wechsel in der SPA

```ts
const locale = useLocaleStore()
await locale.setLocale('de')
```

Aktualisiert `<html lang>`, sorgt dafür, dass jeder spätere Request
`X-Admin-Locale` mitführt, und sendet POST
`/api/admin/system/setLocale {locale: 'de'}`. Eine Locale, die nicht in
`available_locales` enthalten ist, wird mit 422 abgelehnt. Der Server speichert
sie im Attribut `locale` des angemeldeten Benutzers und setzt das Cookie
`admin_locale` (für ein Jahr).

## Inhaltsübersetzung (Modelle)

Verwenden Sie `dskripchenko/laravel-translatable`:

```php
use Dskripchenko\LaravelTranslatable\Traits\TranslationTrait;

class Article extends Model
{
    use TranslationTrait;
}
```

Lesen:

```php
use Dskripchenko\LaravelTranslatable\Models\Language;

$article->t('title');                                  // aktuelle Locale
$article->t('title', null, Language::byCode('de'));    // explizit
Article::whereTranslation('title', 'Hi')->get();
Article::whereTranslation('title', 'like', 'Hi%', 'de')->get();
Article::orderByTranslation('title')->get();
```

## TranslatableField

`TranslatableInput` der Administration rendert ein Eingabefeld mit Tabs — ein Tab
pro Locale:

```php
TranslatableInput::make('title')->locales(['en', 'ru', 'de']),
```

Ohne `locales()` verwendet es `config('admin.ui.available_locales')`;
`->as('textarea')` (oder `markdown`, `wysiwyg`) ändert das innere Steuerelement,
`->requireAllLocales()` macht jede Locale zur Pflicht. Der Formular-State ist eine
`{locale: value}`-Map; beim Anlegen/Aktualisieren entnimmt die Bridge-Schicht
(`TranslatableFieldBridge`) sie dem Payload und speichert jede Locale über den
`TranslationTrait` des Modells.

## Eine Locale hinzufügen

1. Legen Sie `lang/vendor/admin/{locale}/admin.php` und `lang/{locale}.json` an
   (fehlende Schlüssel fallen auf die Fallback-Locale von Laravel zurück).
2. Fügen Sie die Locale zu `config('admin.ui.available_locales')` hinzu:
   ```php
   'ui' => [
       'default_locale' => 'en',
       'available_locales' => ['en', 'ru', 'de', 'zh'],
   ],
   ```
3. Der Locale-Umschalter in der oberen Leiste wird aus dieser Liste befüllt.

## Bewährte Praktiken

- Schreiben Sie Beschriftungen als einfache Quellzeichenketten und übersetzen Sie
  sie in `lang/{locale}.json`, statt sie beim Boot in `__()` zu verpacken.
- Übersetzen Sie keine Code-Bezeichner (Slugs, Rollenschlüssel, Settings-Schlüssel).
- Datums-/Zahlenformate — verwenden Sie ICU über `Intl` (`new Intl.DateTimeFormat`
  im Frontend), implementieren Sie sie nicht von Hand.
- Für längere übersetzbare Inhalte ziehen Sie `TranslatableInput` mehreren
  einfachen Input-Feldern pro Locale vor.
