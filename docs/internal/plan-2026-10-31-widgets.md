# План 2026-10-31: новые виджеты в админке

Цель — всё, что уже умеют встраиваемые виджеты (BPMN/DMN, draw.io, AsyncAPI,
новые нотации диаграмм, доска, канбан, календарь, Markdown-редактор), есть и
в панели — привязанным к данным приложения, а не только к тексту страницы.

## Решения автора

1. **Все четыре формы**: раскладки экранов (`Layout::…`), поля форм
   (`Field\…`), блоки в Markdown/WYSIWYG (```` ```bpmn ```` и т. д.), виджеты
   дашборда.
2. **Канбан и календарь — оба источника**: разметка в поле или блоке (тот же
   формат, что во встраиваемых виджетах) **и** ресурсный вид над Eloquent:
   канбан записей по колонке статуса (перетаскивание меняет статус), календарь
   записей по колонкам дат (перетаскивание переносит).
3. **Доска — совместная, в реальном времени через laravel-realtime**: сервер
   упорядочивает пакеты изменений, присутствие идёт по каналу.

## Что есть в ядре сейчас (карта на 1.62.0)

- Раскладка: PHP-класс с `type()` и `toArray()` → `render/builtin.ts` →
  Vue-компонент; паритет держит `__fixtures__/backend-types.json`
  (`composer types:export`, `BackendTypesFixtureTest`, `backendParity.test.ts`).
  Образец — `Layout\Flow` + `FlowLayout.vue` (+ методы экрана через
  `runMethod`, ленивый `loadFlow.ts`).
- Поле: `fieldType()`, атрибуты → props; правило значения добавляет
  `ValidationRulesExporter` (образец `Field\Flow` + `Rules\FlowModel`);
  типы в `OpenApi\RulesSchema`; страница просмотра — `FIELD_VIEW_TYPES` +
  `infolist/builtin.ts`.
- Блоки: `markdown/blockRenderers.ts` (`builtinMarkdownRenderers`:
  mermaid/openapi/flow/video/audio, тест фиксирует ключи); WYSIWYG берёт те же
  рендереры и строит слэш-команды по ключам (`WysiwygField.vue`, у flow
  команды нет).
- Дашборд: `Widget::widgetType()/data()` → `dashboard/builtin.ts`; настройка
  добавленных пользователем виджетов зашита в `WidgetConfigDialog` /
  `AddWidgetDialog`; раскладка — `admin_dashboard_layouts`.
- Ресурсы: вид только список/дерево (`Resource::viewMode()`); смена одного
  поля — `inlineUpdate` (колонка должна быть `editable`), порядок — `reorder`.
- Реального времени в ядре нет: всё «живое» — опрос. laravel-realtime в
  зависимости ядра не входит.
- Тяжёлые пакеты — внешние в библиотечной сборке и грузятся `import()` по
  требованию; бюджет size-limit в CI не проверяется.

Найденное попутно (чинится в первом же PR, где задето):

- `HtmlSanitizer` разрешает `pre[class]`, но `code` без атрибутов — WYSIWYG
  хранит блок как `<pre><code class="language-X">`, санитайзер включён по
  умолчанию, значит язык блока на сохранении, по всей видимости, теряется.
  Теста нет. Проверить и починить с тестом.
- `readonly` поля — только на клиенте: сервер принимает и сохраняет значение.
  Для полей-редакторов (BPMN, канбан) это заметнее — решить, игнорировать ли
  readonly-поля на сервере (отдельным PR, это поведенческое изменение).
- Бюджет размера не в CI — включить вместе с первыми новыми зависимостями.

### Этап 2. Раскладки экранов — PR «layouts»

`Layout::diagram()`, `bpmn()`, `dmn()`, `drawio()`, `asyncapi()`,
`kanban()`, `calendar()`. Источник, как у `flow`: строка, ключ состояния
экрана или URL (вложение/медиа). Канбан и календарь по разметке — с
`editable()`: изменение уходит методом экрана (`runMethod`), как действия

### Этап 3. Поля форм — PR «fields»

- `Field\Bpmn`, `Field\Dmn` — редакторы пакета bpmn, значение — XML в
  текстовой колонке; правило проверяет, что XML читается пакетом
  (серверная проверка корня и пространства имён).
- `Field\Kanban`, `Field\Calendar` — разметка в текстовой колонке,
  редактируется теми же `UidKanban` / `UidEventCalendar`.
- `Field\MarkdownEditor` — `@dskripchenko/markdown-editor`, значение —
  Markdown (в отличие от `Field\Markdown` — визуальный режим, исходник,
  бок о бок).
- `Field\Board` — см. этап 6 (значение — ссылка на доску).
- Всё — в `FIELD_VIEW_TYPES` и на странице просмотра.

### Этап 4. Ресурсные виды: канбан и календарь — PR «resource views»

- `Resource::kanban()` — колонка статуса, порядок колонок (из enum/опций
  колонки), что показать на карточке (заголовок, теги, исполнитель, срок —
  по колонкам модели), дорожки по ещё одной колонке, лимиты WIP.
  Перетаскивание — смена статуса через тот же путь, что `inlineUpdate`
  (права `.update`, `editableForRow`, правила колонки), порядок внутри
  колонки — через `reorder`, если ресурс сортируемый.
- `Resource::calendar()` — колонки начала/конца (или дата + время),
  заголовок, цвет по колонке; перетаскивание/растягивание — перенос дат с
  той же проверкой; щелчок — карточка/редактирование записи; диапазон
  подгружается через `search` с фильтром по датам.
- Переключатель вида на странице списка: список / канбан / календарь
  (рядом с деревом); вид — часть сохранённого представления (saved views),
  фильтры общие.
- `Layout::resourceIndex()` получает тот же выбор вида.

### Этап 6. Совместная доска — отдельный пакет `laravel-admin-board`

Таблицы и долгоживущий транспорт ядру не нужны всем — по образцу
`laravel-admin-process` это сестринский пакет на плагин-API.

- Таблицы: `admin_boards` (снимок `{board, seq}`, владелец morph, замок),
  `admin_board_batches` (журнал пакетов: `seq`, `client`, `cseq`, ops) с
  обрезкой старых.
- Сервер: порт `BoardServer` на PHP — нумерация пакетов в транзакции с
  блокировкой строки доски, повторы по `client`+`cseq`, лимиты (500 операций
  в пакете, 10 000 объектов), замок принимает только настройки; права
  просмотра/правки перед приёмом.
- Транспорт: HTTP-контракт `@dskripchenko/board` (`snapshot`, `batches`,
  `presence`) — работает везде; при установленном laravel-realtime пакеты и
  присутствие рассылаются по приватному каналу доски, клиент — провайдер
  поверх `@dskripchenko/realtime` (отправка остаётся HTTP — порядок задаёт
  сервер), long polling — запасной путь.
- В панели: ресурс «Доски», `Layout::board()`, `Field\Board` (доска,
  привязанная к записи), виджет дашборда.
- Проверка: несколько клиентов на одной доске (как тесты пакета: случайные
  сценарии, одинаковый итог), отказ транспорта, замок, права.

## Этап 6 — контракт ядра и пакета доски

Ядро (`Layout::board()`, тип раскладки `board`, и виджет дашборда `board`)
рисует `BoardEditor` из `@dskripchenko/board/vue` со своим провайдером; пакет
`laravel-admin-board` хранит доски и упорядочивает изменения. Граница — этот
контракт; ни ядро не знает таблиц пакета, ни пакет — устройства редактора.

**Свойства раскладки** (их собирает пакет, ядро только рисует):

| Ключ | Что |
|---|---|
| `endpoint` | Базовый путь API доски относительно клиента панели (`getAdminClient()`), например `/boards/42` |
| `readonly` | Только просмотр: редактор не шлёт пакеты (сервер всё равно проверяет право) |
| `user` | `{ id, name, color }` — кто я для присутствия и курсоров |
| `realtime` | `{ ticketUrl, channel }` или `null`: подписка на канал laravel-realtime |
| `pollInterval` | Мс между опросами без realtime (по умолчанию 1500) |
| `title`, `height` | Как у остальных раскладок |

**API пакета** — POST JSON через клиент панели (та же сессия, CSRF, слои):

| Запрос | Тело | Ответ |
|---|---|---|
| `{endpoint}/snapshot` | — | `{ board, seq }` |
| `{endpoint}/batches` | `{ client, cseq, ops }` | `{ seq }`; повтор уже принятого пакета — тот же `seq`; 403 без права правки; 422 сверх лимитов |
| `{endpoint}/poll` | `{ after }` | `{ batches }` — пакеты с `seq > after`; 410, если `after` старше журнала (клиент перезагружает снимок) |
| `{endpoint}/presence` | `{ client, user, cursor?, selection? }` | `{ presence }` — все, кого сервер видел за 30 с |

**Realtime.** Если у хоста стоит laravel-realtime и пакет включил его, после
приёма пакета сервер публикует в приватный канал `admin-board.{id}` событие
`batch` (пакет с `seq`), а после `presence` — событие `presence` (весь список).
Клиент подписывается через `RealtimeClient({ ticketUrl })` из
`@dskripchenko/realtime`, применяет пакеты по порядку и после переподключения
добирает пропущенное через `poll`. Клиент `@dskripchenko/realtime` (опубликован в npm
вместе с laravel-realtime 0.1.0) — зависимость ядра, загружается по требованию;
`setBoardRealtime()` подменяет его своей сборкой хоста. Не загрузился — опрос. Без realtime клиент опрашивает `poll` раз в
`pollInterval`. Long polling не используется: он держит воркеры PHP-FPM.

**Семантика** — как у эталонного `BoardServer` пакета `@dskripchenko/board`
(`board/src/sync/server.ts`) и его модели операций (`board/src/model/ops.ts`):
порядок задаёт сервер, `set` — последняя запись в порядке сервера, `delete`
побеждает, заблокированная доска (`meta.locked`) принимает только операции
`meta`, лимиты — 500 операций в пакете и 10 000 объектов на доске.
