# i18n

Два слоя:

1. **Перевод интерфейса** — оболочка админки, подписи полей, пункты меню.
2. **Перевод контента** — поля Eloquent-моделей, хранимые по локалям
   (через `dskripchenko/laravel-translatable`).

## Определение локали

`LocaleResolver` (его применяет middleware `AdminLocale`) берёт первое из
перечисленного, что входит в `config('admin.ui.available_locales')`:

1. query-параметр `?locale=en` (явное переопределение — для тестов и превью)
2. заголовок `X-Admin-Locale` (его шлёт SPA)
3. атрибут `locale` вошедшего пользователя
4. cookie `admin_locale`
5. заголовок `Accept-Language` (`ru-RU` сводится к `ru`)
6. `config('admin.ui.default_locale')` (`ADMIN_LOCALE`), а если не задан —
   локаль приложения

Выбранная локаль применяется через `app()->setLocale()` и попадает в
bootstrap (`locale`, `availableLocales`) и в manifest.

## Языковые пакеты интерфейса

Пакет поставляет строки двух видов, обе приходят в SPA в мешке
`translations` из bootstrap:

- `resources/lang/{en,ru}/admin.php` — namespace `admin::`; вложенные
  массивы разворачиваются в ключи вида `admin.common.save`, фронтенд читает
  их через `t('admin.common.save')`.
- `resources/lang/en.json` — JSON-словарь, ключ которого — исходная
  русская строка; через него `tr()` фронтенда переводит встроенные строки
  компонентов.

Это обычные переводы Laravel, поэтому host переопределяет их
по-ларавельному:

```php
// lang/vendor/admin/de/admin.php — the admin:: namespace for a new locale
return [
    'common' => [
        'save' => 'Speichern',
        'cancel' => 'Abbrechen',
    ],
    // ...
];
```

а JSON-строки добавляет или переопределяет в своём `lang/{locale}.json`.

Собственные подписи (ресурсов и полей, пунктов меню, actions, тексты
подтверждений) не нужно оборачивать в `__()`: при сериализации manifest'а
и схем они проходят через JSON-переводы локали запроса, а строка без
перевода возвращается как есть.

## Смена локали в SPA

```ts
const locale = useLocaleStore()
await locale.setLocale('de')
```

Обновляет `<html lang>`, добавляет `X-Admin-Locale` ко всем следующим
запросам и отправляет POST `/api/admin/system/setLocale {locale: 'de'}`.
Локаль вне `available_locales` отклоняется с 422. Сервер сохраняет её в
атрибут `locale` вошедшего пользователя и ставит cookie `admin_locale`
(на год).

## Перевод контента (модели)

Используйте `dskripchenko/laravel-translatable`:

```php
use Dskripchenko\LaravelTranslatable\Traits\TranslationTrait;

class Article extends Model
{
    use TranslationTrait;
}
```

Чтение:

```php
use Dskripchenko\LaravelTranslatable\Models\Language;

$article->t('title');                                  // current locale
$article->t('title', null, Language::byCode('de'));    // explicit
Article::whereTranslation('title', 'Hi')->get();
Article::whereTranslation('title', 'like', 'Hi%', 'de')->get();
Article::orderByTranslation('title')->get();
```

## TranslatableField

`TranslatableInput` админки рисует поле с вкладками — по вкладке на
локаль:

```php
TranslatableInput::make('title')->locales(['en', 'ru', 'de']),
```

Без `locales()` берётся `config('admin.ui.available_locales')`;
`->as('textarea')` (или `markdown`, `wysiwyg`) меняет внутренний контрол,
`->requireAllLocales()` делает обязательными все локали. Состояние формы —
карта `{locale: value}`; при create/update слой-мост
(`TranslatableFieldBridge`) забирает её из payload и сохраняет каждую
локаль через `TranslationTrait` модели.

## Добавление локали

1. Создайте `lang/vendor/admin/{locale}/admin.php` и `lang/{locale}.json`
   (недостающие ключи берутся из fallback-локали Laravel).
2. Добавьте локаль в `config('admin.ui.available_locales')`:
   ```php
   'ui' => [
       'default_locale' => 'en',
       'available_locales' => ['en', 'ru', 'de', 'zh'],
   ],
   ```
3. Переключатель языка в верхней панели строится по этому списку.

## Рекомендации

- Пишите подписи исходными строками и переводите их в
  `lang/{locale}.json`, а не оборачивайте в `__()` при загрузке.
- Не переводите идентификаторы кода (slug'и, ключи ролей, ключи настроек).
- Форматы дат и чисел — через ICU/`Intl` (`new Intl.DateTimeFormat` на
  фронтенде), не вручную.
- Для длинного переводимого контента используйте `TranslatableInput`, а не
  несколько обычных Input-полей по локалям.
